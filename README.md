## Description

Text-to-SQL systems let users query relational databases in natural language. In an organisation
with many databases, such a system must first find which database and which tables a question
refers to. This step is called **schema routing**. For example, for the question "Which language is
the most popular on the Asian continent?", the router should return the database `world_1` with
the tables `country` and `countrylanguage`.

**DBCopilot** (Wang et al., EDBT 2025) performs schema routing with a trained T5 model. The model
learns the schemas of a collection of databases and writes out the database and table names
directly. It is trained on 100,000 synthetic questions, generated by a second T5 model from random
walks on the schema graph. Training takes 13,678 seconds on A100 GPUs for each collection.

This project asks whether a method that **requires no training** can match DBCopilot. We built it
in two stages.

1. **Graph retriever.** A standard retriever (BM25 or the dense retriever SXFMR) scores every table
   against the question. These scores, the *seeds*, are then passed along the foreign-key links
   between tables, using the same table graph as DBCopilot. This step lifts join tables that share
   few words with the question. Finally, each database is ranked by the average score of its
   tables in the top 100.
2. **GraphRAG.** We improved the seed scores of the graph retriever in three ways:
   - **Hybrid seeds:** BM25 and dense scores are combined.
   - **Reranking:** a pretrained cross-encoder re-scores the top 50 tables.
   - **Table descriptions:** a short description of every table is written by a small language
     model (`qwen2.5:7b`) running locally on a laptop.

   The graph retriever with all three improvements is what we call GraphRAG.

We compare against DBCopilot's reported results. To make this comparison valid, we first reproduced the paper's own BM25 and dense baselines: all 40
compared values are within one point of the paper's. All settings were chosen on training
questions only, and each test set was run once.

## Results

We used five benchmarks: Spider, Bird, Fiben, and two reworded versions of Spider (Spider-syn and
Spider-realistic). The metrics are the paper's own:

- **DR@k:** the share of questions whose correct database is in the top *k*.
- **TR@k:** the share of required tables found in the top *k*, pooled over all questions as in
  DBCopilot's evaluation.

| Dataset | DR@1 (GraphRAG / DBCopilot) | DR@5 | TR@5 | TR@15 |
|---|---|---|---|---|
| Spider | 81.82 / **85.01** | **97.39** / 96.42 | **95.78** / 91.63 | **99.23** / 97.51 |
| Bird | 86.96 / **88.92** | **98.11** / 97.13 | **87.24** / 85.83 | **95.47** / 94.59 |
| Fiben | – | – | 37.89 / **41.12** | 50.52 / **56.89** |
| Spider-syn | 56.67 / **62.67** | **87.62** / 85.11 | **77.89** / 70.35 | **91.95** / 86.26 |
| Spider-realistic | 75.79 / **79.53** | **97.24** / 95.47 | **91.11** / 87.93 | **97.20** / 96.06 |

DBCopilot values are as reported in the paper. Fiben contains a single database, so only table
recall applies to it.

**What the results show:**

- **Table recall.** GraphRAG finds more of the required tables than DBCopilot on four of the five
  benchmarks, at both 5 and 15 tables. The largest gain is on Spider-syn, 7.5 points of TR@5.
- **DR@5.** GraphRAG has the correct database among its top five more often than DBCopilot on all
  four multi-database benchmarks.
- **DR@1.** DBCopilot ranks the correct database first more often on every benchmark. This is
  because we rank a database by the average score of its tables: a database with a few strongly
  matched tables can outrank the correct one. On Spider, 78% of the questions where our first
  database is wrong still have all their required tables in our top five.
- **The graph.** On its own, the graph improves on the retriever it starts from in 74 of 120
  paired t-tests and is worse in only 2, both on Fiben. It helps most on questions that join
  several tables. On Bird, recall@5 of bridge tables rises from 51% to 72% with BM25 seeds.
- **Wording.** From Spider to Spider-syn, DR@1 falls by 11.5 to 12.8 points for the dense graph
  retriever, compared with 22.3 points for DBCopilot.
- **Cost.**
  - The graph retriever needs no training. It is built in under 8 seconds on a laptop and answers
    203 to 857 questions per second, compared with DBCopilot's 43.
  - Writing the table descriptions takes 51 minutes, once.
- **Fiben.** DBCopilot remains better on Fiben. Its schema has long concatenated table names, and
  its foreign-key graph is very dense: 62% of table pairs are linked.
